ASPECT RATIO: 3:2 (1600w × 900h logical units)
STYLE: Publication-quality academic diagram. Clean serif font (Georgia or similar). Two-panel side-by-side comparison. Minimal decorative elements. No gradients, no drop shadows.

=== CORE ARCHITECTURE (applies to BOTH panels) ===
BOTH panels share the same base infrastructure:
  User → LLM → MCP Server → Census Data API → (data returns to MCP Server) → (MCP Server returns to LLM) → (LLM responds to User)

There is NO separate Response box. The flow closes when the LLM returns the answer to the User via a return arrow. User is both the start and end of the flow.

The ONLY structural difference between panels:
- LEFT: LLM also queries a client-side Vector DB (bolt-on, external to MCP Server)
- RIGHT: MCP Server also queries a server-side Pragmatics Sidecar (cloud database)

=== KEY VISUAL ARGUMENT ===
The diagram makes one argument:

LEFT:  Vector DB (grey) attaches at the CLIENT layer — next to LLM. Client-maintained. One extra client-side component.
RIGHT: Pragmatics Sidecar (orange) attaches at the SERVER layer — next to MCP Server. Server-maintained. No client-side addition.

The vertical position of the bolt-on component IS the argument. Everything else is symmetric.

There is no separate Response box on either side. The LLM returns an answer to the User via a return arrow — the loop closes at the User node.
